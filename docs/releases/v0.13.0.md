# v0.13.0 — Routines

Agents can now act on a schedule. A routine is a named prompt an agent runs on its own, once or on a repeating schedule, even while you are away; each run starts a new chat, and you can let an agent schedule its own follow-ups, with your approval if you want it.

## Added
- **Routines.** A new Routines tab in each agent's editor:
  - Create a routine with a name, a prompt and a schedule: once at a date and time, in a few minutes, hours or days, or immediately; or repeating every N minutes, hours, days, weeks (on chosen days), months (on a day or a weekday such as "the last Friday") or years, ending never, on a date or after a number of runs.
  - The form offers presets ("Every weekday", "Weekly on Thursday", "Monthly on the last Friday", …), a Custom recurrence dialog, and a preview line with the next run and any warning (for example, months without a 31st are skipped).
  - Schedules follow your time zone (Settings › Date and time), including across daylight-saving changes.
  - Each routine is a card with a switch, its schedule, the next and last run, and a "⋯" menu with Run now, Edit and Delete. Its Details show the prompt and recent runs, each with an Open chat link.
- **Every run starts a new chat**, titled with the routine's name. The routine's message is marked as the routine's (a "Routine" chip), and the chat's agent panel shows which routine started it and lists the agent's routines.
- **Honest run history.** Each run records what happened: Ran, Caught up (a run missed while the app was closed, run once on return if it was recent), Missed (too long ago; a backlog is never run), Skipped (the previous run was still going), Stopped, Interrupted (the app stopped mid-run) or Failed, with the reason.
- **Agents can schedule their own routines.** On the Self-configuration tab, turn on "Let this agent manage its routines". The agent can then list, schedule, change and cancel its routines (for example "check back with me in two hours").
  - With "Require approval" on, each change waits for you under "Waiting for approval", with Approve and Dismiss; a change made stale by your own edit asks before it overwrites.
  - Every change the agent makes is kept in the item's History.
  - A routine the agent wrote after reading content that didn't come from you (a web page, a message from someone else) is flagged "Check this" wherever it appears. Saving it from the edit form clears the flag.
  - Limits keep it bounded: at most 50 active routines per agent, at most 5 changes per reply, and every refusal tells the agent why.
- To have a routine message you on Discord or another connected platform, say so in its prompt; the agent posts with its platform tool.

## Changed
- The **Self-configuration** tab is now two cards, Agent prompt and Routines, each with its own switch, a "Require approval" switch, and Waiting for approval and History sections. External access is at the bottom of the page.
- The agent editor's **MCP servers** are now part of the **Tools** tab, listed above the built-in tools.
- The **General** tab's danger zone explains its two actions: "Purge chats and history" (deletes the agent's chats, its routines' run history and its finished approval history; keeps the agent, its routines, rules and notes) and "Permanently delete agent".
- Chat history retention also clears an agent's finished routines and resolved approval history.

## Fixed
- Opening a chat while its agent was starting a turn could leave that turn's messages unsaved.
- After a purge, the Purge now button no longer stays armed.
- Creating an agent with an unknown model provider now says so instead of failing with a server error.
- Errors in the agent editor's header are announced to screen readers.

## Notes
- The database is upgraded automatically (schema 44 to 49). Nothing needs to be reconfigured, and every agent keeps its current self-configuration settings.
- Routines run only while the app is running. A routine due while it was closed runs once when the app returns if the miss is recent; otherwise it is recorded as missed.
- For API users: routine routes are under `/api/agents/{name}/routines`, and a schedule is `{start, repeat, ends}`.
