## Executive Summary

The codebase is in **healthy shape post-Mission-05**, with a strong baseline in security-bearing surfaces (resolver narrow-only invariant, SSRF resolve-then-pin with SNI preservation, subprocess env allowlist, filesystem scope-first ordering, PTY cross-agent isolation, fully parameterized SQL, no `shell=True`) and accessibility (skip-link, semantic landmarks, focus-visible, ARIA tablist, focus trap on modals, 42/42 design-token contrast tests passing). What surfaced is mostly small-but-real: 0 critical, 14 Action Required, 28 Advisory, 7 Pass. Key new findings: Concourse passwords in git history (private repo + localhost-only Concourse downgrades severity from CRITICAL to Action Required), 2 failing tests on `main` (one is the F1-known `--font-size-h3` red, one is a host-vs-container CWD-coupling test bug), CI does not run `ruff check` or `ruff format --check`, three high-impact a11y gaps in the chat surface (no live region, unlabeled input, mouse-only tooltips), and one false-positive risk in `auto-rollback` (re-tags but never re-verifies health). Cross-checking against M01-M04 debriefs revealed strong continuous-improvement signal — 11 categories of debt were systematically absorbed mission-over-mission — and a small set of architectural lingerers (per-provider streaming-parser duplication, `_run_command` subprocess helper, `_sessions` eviction, singleton aiosqlite, per-call `httpx.AsyncClient`) that are too large for a quick-win pass and are surfaced here for tracking.

**Recurring lingerers** (flagged across multiple debriefs, not absorbed; surface here for tracking — too architectural for quick-win flight):

4. **Singleton aiosqlite** (M03) — pattern issue; deferred.
5. **Per-call `httpx.AsyncClient`** (M03 + INSP-20) — confirmed across two inspections. Lifespan-scoped client would amortize TLS handshakes.
6. **WebSocket protocol-shape tests absent** (M02, M03) — no tests pin `session_joined` payload invariants or message-type contracts.
7. **v_n→v_n+1 migration tests absent** (M03) — only fresh-DB migration tested; per-version regression risk.
8. **Tool-implementation unit tests** (M01 mission debrief, biggest test gap) — partially addressed by M05's +75/+150/+157 test additions (filesystem, execution, web). Status of pre-M05 tools unknown.

- **Single-wave 4-agent partition was correct** for medium project size. No agent hit context limits; outputs returned within budget.
- **Spawning the prior-mission debt-context loader after the first synthesis pass was the right ordering** — let the inspection findings stand on their own first, then refined classification with prior-debrief context. Future inspections of mature projects should follow the same pattern.
- **Roundtable was skipped** because Architect's challenges were severity calibration grounded in documented project posture, not factual disputes. Saved a cycle without compromising quality. Future inspections should reserve roundtable for findings where the reviewer's evidence-base is genuinely contested.
- **First-time maintenance for a project with rich debrief history requires loading prior debriefs**. The user surfaced this gap when asked. For ongoing inspections, cumulative known-debt context is established once and only the delta matters; for first-time inspections, the prior-debrief pass is essential.

## Recommendations

1. **Land the maintenance mission** — 7-bundle Flight 1 covers all 14 Action Required findings as quick wins (~3 hours of focused work). All bundles are ≤4 file touches, no schema/migration churn, no architectural change.
2. **Defer architectural lingerers** to dedicated future flights (provider-streaming consolidation, subprocess helper extraction, observability backbone) — these are mission-sized, not maintenance-sized.
3. **Schedule a dependency-bump flight** as Flight 2 of the maintenance mission (or as an independent flight) — one-shot bulk update of 16 outdated deps + verify tests green. Independent risk profile from the quick-wins flight.
4. **Adopt `pip-audit` in CI** before MCP work begins — MCP brings additional library surface; CVE awareness is cheap insurance.
5. **Document the project's threat model explicitly** as part of Bundle G — the no-auth posture is correct for the use case, but explicit documentation prevents future re-discovery and converts an implicit decision into an inheritable contract.
