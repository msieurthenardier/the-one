# v0.14.0 — One MCP server, a key for each agent

One MCP server in the Library can now be shared by many agents, each connecting with its own header values (HTTP servers) or environment variables (stdio servers), such as its own API key, and each seeing the tools that key allows.

## Added
- **Per-agent credentials on the Tools tab.** An agent's tile for an MCP server now shows the server's headers (or environment variables) in the same table the Library uses.
  - The table is locked by default and shows the Library's values. **Override headers** unlocks it so you can add, change or remove this agent's own rows.
  - The tile's own **Save** writes the agent's values immediately, without the agent's main Save.
  - In the Library, the server's editor now hints: "Optionally override headers in agent settings."
- **Sensitive, per row.** Each row has a Sensitive switch. Sensitive values stay masked. Values you mark non-sensitive are shown in clear on the agent's tile (they are still encrypted when stored). An Authorization header is always masked. On a server that uses OAuth sign-in, a per-agent Authorization header is refused, because sign-in supplies it.
- **Each agent sees its own tools.** Switching a server on for an agent, or pressing **Test**, connects with that agent's own values and lists the tools its key allows.

## Changed
- **A saved credential change applies on the agent's next tool call**, including in a chat that is already open. There is no need to start a new chat.
- A header or environment variable left blank in the Library is no longer sent to the server.
- The Tools tab's Refresh button is gone; Test does the same job, with the agent's own values.

## Notes
- The database is upgraded automatically (schema 49 to 50, a new table only). Nothing needs to be reconfigured.
- An agent that already has credential overrides lists that server's tools live the first time it is built after the upgrade, then remembers them.
