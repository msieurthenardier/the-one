# v0.16.1 — Chats recover from an interrupted tool call

A chat that was stopped while the agent was using a tool keeps working, and a dropped MCP connection no longer stops the agent.

## Fixed
- **A chat no longer gets stuck after an interrupted tool call.** If a turn was stopped while a tool was running, every later message in that chat could fail on Claude with an error about a `tool_use` without a `tool_result`. The interrupted tool call is now recorded as an error result, and the agent carries on. Chats that were already stuck recover the next time you open them and send a message.
- **A dropped MCP connection no longer stops the agent.** When an MCP server's connection died during a chat, the agent's next call to that server ended the turn as if you had pressed Stop. The app now reconnects and the turn continues.
- **An interrupted reply is no longer repeated.** The "interrupted" message at the end of a stopped turn repeated the agent's earlier replies from that turn. It now holds only the reply that was cut off.

## Notes
- No database upgrade, and nothing needs to be reconfigured.
