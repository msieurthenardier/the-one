# v0.13.1 — Tool overrides that fit, and a simpler self-configuration

An agent's tool settings can no longer go outside the app-wide settings, can no longer break a chat when the app-wide settings change, and now record only what you actually change. The self-configuration server leaves the Tools tab: the Self-configuration tab is now the only place it is controlled.

## Changed
- **Agent tool settings are checked when you save.** On an agent's Built-in tools tab, a value that goes outside the app-wide setting (for example, an allowed folder that the app-wide Allowed paths does not include) is refused on the field. The message names the tool and tells you where to change the app-wide setting. Nothing is saved.
- **Only the values you change are stored.** Opening a tool's settings on an agent and saving no longer copies the app-wide values into the agent. Each field shows whether it is inherited or the agent's own, with a Reset back to inherited.
- **Tightening an app-wide setting no longer breaks agents.** When an agent's own value no longer fits (say you removed a folder from the app-wide Allowed paths), the agent keeps working with the part both allow, instead of failing to start a chat. A notice explains what was dropped and offers a one-step fix. It shows in the chat's agent panel, on the agent's Built-in tools tab and its row in the Agents list, and on the field itself. Before you save an app-wide change, Settings › Built-in tools lists the agents it would narrow.
- **The path fields say how Shell and Python are limited.** When an agent has Shell or Python on, its Allowed paths and Denied paths explain how those tools are confined on this computer, and that turning them off keeps the agent to its paths.
- **The self-configuration server is no longer on the Tools tab.** It used to appear there as a locked row whose individual tools could be unchecked. Now Agent prompt on the Self-configuration tab is the only control, and when it is on the agent has all four of its tools. To keep an agent's prompt edits under review, turn on "Require approval for prompt edits".
- The app log now has one line for each routine decision: each scheduled, caught-up, missed or skipped run, each run's start and outcome, each approval decision and each history purge.

## Fixed
- A web tool that follows a redirect now refuses a site your Allowed or Denied sites forbid, exactly as it refuses that site as the first address.
- A connector's editor that was open while a new peer paired no longer drops that peer when you save.
- Saving an agent before its model list has loaded keeps the stored model.
- A file added on its own to a knowledge base is indexed straight away.
- A link in an agent reply can no longer reach another site through backslashes or hidden control characters.
- On Windows, terminal control sequences no longer appear in Shell output.
- The Settings › Encryption count of stored secrets is correct when the key comes from the environment.
- Choosing Quit from the tray just as the app finishes starting no longer leaves its window open with no tray icon.
- The knowledge-base detail panels tell screen readers when they have finished loading.

## Notes
- No database changes.
- **Two one-time cleanups run at first start:**
  - Tool values that earlier saves copied into agents from the app-wide settings are removed, so those agents follow the app-wide setting again. Values you changed deliberately are kept.
  - Any per-agent withholding of self-configuration tools is removed. An agent that had a self-configuration tool unchecked gets it back while Agent prompt is on.
- Running from source or installing with pip now needs Python 3.12 or newer. The installers bundle their own Python, so nothing changes for them.
- For API users:
  - `PUT /api/agents/{name}` returns 422 for a tool override that widens the app-wide setting. It also returns 422 for any per-agent setting of the `self-configuration` MCP server.
  - Agent responses include a `notices` list.
  - Deleting a knowledge-base file item that a folder walk created returns 409, because the next walk would bring it back. Remove its folder instead.
  - An agent PUT never attaches or detaches the self-configuration server; only the Self-configuration routes do.
