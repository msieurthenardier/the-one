# v0.11.8 — Signing in to MCP servers from the desktop app

Signing in to an MCP server now works in the desktop app: the sign-in page opens in your browser and your agent carries on when you're done. And when a server rejects the key you configured, the app now says so instead of offering a sign-in that can't work.

## Fixed
- In the desktop app, signing in to an MCP server no longer stops at "Popup blocked". The sign-in page opens in your browser (or use the "Open sign-in page" link, with a Copy button beside it), and the MCP editor notices when you're done and lists the server's tools.
- When a chat needs you to sign in to an MCP server, finishing the sign-in now resumes the tool call and the agent continues. Before, the chat showed "Resuming…" and stopped.
- The "Log in" button in a chat now always starts a fresh sign-in, and it stays visible instead of being tucked inside the collapsed "Tool activity" section.
- When an MCP server rejects the key or headers you configured, Test connection and the chat now say "The server rejected the configured credentials" instead of offering a sign-in. This covers servers like Goldfinch that use keys rather than sign-in.
- The Refresh connection and Reset connection buttons in the MCP editor line up with the rest of the form.
- Sign-in links only open real web addresses.
- Keyboard and screen-reader improvements in sign-in: focus moves to the sign-in link and back to where you can continue, status messages are announced, and Copy reports whether it worked.

## Notes
- Nothing to reconfigure, and no database changes.
- If an MCP source shows "The server rejected the configured credentials", check the `Authorization` header (or other headers) on that server in Library › MCP servers, or the agent's MCPs tab if it overrides them.
