# v0.15.1 — Tools up front on small local models, and Claude prompt caching

Agents on small local models can use their tools straight away, and chats on Claude reuse the cached prompt from one turn to the next.

## Changed
- **Small local models get their tools up front.** When the model provider reports the model's context window and the agent's enabled tools fit comfortably in it, every enabled tool is given to the agent at the start. The agent no longer has to find a tool with `search_tools` first. Otherwise tool discovery works as before. Two environment variables tune this: `THE_ONE_TOOL_EXPOSURE_FRACTION` (the share of the context window the tools may use, default 0.25; `0` turns it off) and `THE_ONE_TOOL_EXPOSURE_CEILING_TOKENS` (default 8000). They are read from the process environment only, not from `.env`.
- **Claude chats use prompt caching.** On all three Claude provider types (API key, Claude Plan (OAuth) and Claude Plan (Token)), each request marks the tool definitions, the system prompt and the conversation so far for caching. Later turns in a chat can then reuse them instead of sending them again in full. A model only caches once the prompt reaches its minimum size; on Claude Haiku 4.5 that is 4096 tokens. If an endpoint refuses caching, the app retries without it. The context and usage readouts are unchanged: they still show the whole prompt.

## Fixed
- In an agent's Tools tab, an error saving the Secrets section is now announced to screen readers and tied to the secret switches. The next toggle clears it.

## Notes
- No database upgrade, and nothing needs to be reconfigured.
