## Outcome Assessment

### Objectives Achieved

The flight delivered the foundational OAuth surface end-to-end: SDK-driven auth-code-with-loopback flow consumed via `mcp.client.auth.OAuthClientProvider`; encrypted token storage extending F1's `secrets` JSON blob with strict GET-strip + PUT-preserve protection for the four OAuth-managed keys; a `ManualOAuthClientProvider` subclass that overrides `async_auth_flow` verbatim minus the discovery + DCR steps for non-spec-compliant AS targets (e.g. GitHub MCP); generic `metadata: dict | None` field on the provider-neutral `ToolResult` type with a multi-tool-call deferral semantic in the agent loop; `auth_required` / `auth_resolved` / `auth_failed` WebSocket protocol; chat UI with inline Login-required button + modal + manual-entry form; pool integration that constructs an `OAuthClientProvider` (or `ManualOAuthClientProvider`) when `dcr_credentials` is present in source secrets; full-scope chat UI flow including `/api/oauth/start` background-task trigger and `/api/oauth/manual-register` persistence.

The L1 dispatcher rewrite (non-CM `_open_streamable_http_transport_stack` + `_open_stdio_transport_stack` consumed by `MCPClient._transport_connect`) ships as a speculative mechanism — the F4-HAT-Finding-#1 retirement claim is empirically unverified pending a HAT that did not run in this session. L6 HAT (the binary go/no-go gate per flight.md §10) was deferred and is rolled forward into F6 scope.

## What Went Well

- **SDK consumption decision (Architect cycle-1 H1) was the single biggest scope reduction of the flight.** Original design draft would have written `pkce.py` + `discovery.py` + `registration.py` + `flow.py` (~400-600 LOC). Cycle-1 found that `mcp.client.auth.OAuthClientProvider` (in pinned `mcp==1.27.0`) already ships PKCE, RFC 9728 PRM discovery, RFC 8414 AS metadata discovery (with OIDC fallback), RFC 7591 DCR registration, RFC 8707 audience validation, and pre-emptive token refresh. The flight collapsed to a ~250 LOC adapter layer (the original §11 estimate; actual `oauth/` package landed at ~963 LOC because cycle-2 expansions added the full-structure `ManualOAuthClientProvider.async_auth_flow` override and the `provider_factory.py` factory function). Net win: spec-compliance risk eliminated entirely; only adapter + integration code is the-one's responsibility.

- **Two-cycle Architect review at flight design caught two load-bearing architectural decisions.** Cycle-1 H1 forced the SDK consumption pivot. Cycle-2 NEW-H1+H2 caught that `OAuthClientProvider.__init__` has no kwarg to inject pre-known AS metadata AND that `async_auth_flow` always runs discovery — this drove the user-picked Option B subclass-with-verbatim-override pattern for `ManualOAuthClientProvider`. Without these cycles, `manual_metadata.py` would have shipped as a ~50 LOC module that doesn't actually skip discovery (silently triggering discovery against AS endpoints that don't serve `/.well-known/`).

- **Per-leg cycle-1 design review hit rate of 4/5 caught real implementation-time bugs.** L1 cycle-1: vacuous mock test would have passed pre-and-post source rewrite. L2 cycle-1: 5 highs including `OAuthToken.expires_in` (relative duration) vs. `expires_at` (Unix epoch) translation gap; `make_callback_handler(state)` factory unimplementable because state is generated INSIDE the SDK flow; chat_session_id plumbing acknowledged in code comment but not promoted to acceptance criteria. L3 cycle-1: 7 highs including fictitious `_tool_result_from_dict` deserialization function (deserialization is INLINE in `message_from_dict` at `db/codec.py:46-52`); WebSocket router uses `action` not `msg_type`; class-vs-flat function naming convention mismatch. L4 cycle-1: 3 highs including invented `_get_mcp_repo()` helper (no such function exists; real pattern is `get_connection() + get_encryptor() + MCPSourceRepository(...)` per `_pool.py:142-145`); WWW-Authenticate parameter name `resource_metadata` not `resource_metadata_url`. L4 cycle-2: probe import error `streamablehttp_client` (deprecated, no `http_client=` kwarg) vs `streamable_http_client` (current, what the_one's transport uses). Each finding would have caused a `NameError`/`ImportError`/`AssertionError` on first run; the cycle-1 reviewer caught them all at design-doc layer.

- **Stake-test pattern continues to pay dividends** (per F2/F4 debrief KL #1). L1 ships speculatively against the F4-HAT-Finding-#1 retirement claim with an explicit caplog assertion deferred to L6 HAT. L2's `test_async_auth_flow_body_shape_pinned` (L4-A12b after cycle-2 substring correction) uses `inspect.getsource(OAuthClientProvider.async_auth_flow)` to assert presence of 6 stable substrings — `"for url in"`, `"_perform_authorization()"`, `"_handle_token_response"`, `"_add_auth_header"`, `"if response.status_code == 401"`, `"elif response.status_code == 403"`. On any upstream `mcp` SDK refactor, this test breaks before the override silently misbehaves. L4's A9 stake-test probe revealed `ExceptionGroup wrapping httpx.HTTPStatusError` — A9 shipped using Python 3.11+ `except*` syntax rather than being deferred. The pattern is now codified across three legs.

- **Generic `metadata: dict | None` field on `ToolResult`** (cycle-1 H3 architectural decision) held up cleanly. The alternative — a domain-specific `is_auth_required: bool` field on the LLM-base type — would have coupled the provider-neutral type to MCP OAuth semantics. Generic field has zero marginal cost vs. typed boolean, and is documented for future cross-provider use cases (token-usage reporting, MCP elicitation events). The `continue` virtual-signal carve-out (cycle-2 M4) — synthesized `ToolResult` always has `metadata=None` because it's assembled inline at `agent/core.py:113-122` bypassing `_execute_tool` — is documented in the leg artifact and tested directly via `test_continue_signal_metadata_is_none`.

- **GET-strip + PUT-preserve invariant** (cycle-1 M2) is structurally robust. Single named constant `_OAUTH_MANAGED_SECRET_KEYS = frozenset({...})` at `api.py:518` is referenced at both the GET-strip site (`_mcp_source_response`) and the PUT-preserve site (`update_mcp_source`). Three-test coverage (GET-strip; PUT-preserves under attacker payload; PUT-preserves under innocent `__MASKED__` payload). The most likely breakage vector — operator re-saving via Settings form — is the second test case.

- **Multi-tool-call deferral semantic** (flight §4 cycle-1 M1) is the right semantic. When `[tc_A, tc_B, tc_C]` arrives and `tc_B` returns `metadata.is_auth_required=True`, tc_A's result has already landed in messages (rolling back would corrupt history); tc_B's auth_required tool_msg is yielded so chat history reflects the surface; tc_B + tc_C are deferred as `_deferred_tool_calls`; broadcast fires; step exits early. On `auth_resolved`, `Agent.resume_after_auth([tc_B, tc_C])` re-dispatches in order. Tested via `test_pause_at_tc_b_defers_tc_b_and_tc_c` + 7 other agent-loop tests in `test_agent.py`.

- **Worker-task-per-entry pattern from F4 inherits cleanly into F5's refresh path** (flight §12). Token refresh runs inside the SDK's `OAuthClientProvider.auth_flow` generator inside the same task as the `_entry_worker` — cross-task disconnect is structurally impossible for refresh-triggered reconnects. The F4 architectural decision compounds well; no F5-specific cross-task safety code needed.

- **Cycle-1 + cycle-2 escalation discipline produced the right outcomes.** L2 cycle-2 NEW-H1 (full `async_auth_flow` body shape) was a sizing correction not a design disagreement; user picked Option A inline (apply the rewrite) and the leg landed cleanly with the verbatim-override pattern. L4 cycle-1 H1 (`_get_mcp_repo()` invention) collapsed to "L4 scope is bigger than necessary"; user picked Option B (passthrough-only); the resulting smaller L4 was clean. L5 cycle-0 (lazy-path consent_url=None requires SDK-flow trigger); user picked Option A (full-scope L5). All three escalations were genuine architectural decision points; the agentic-workflow's 2-cycle cap correctly forced the human-in-the-loop call rather than letting the orchestrator flail.

- **Accessibility Reviewer caught 2 blocking WCAG issues that the implementer missed.** WCAG 1.4.3: `.modal-dialog-message` used `--fg-secondary` (#888888) on `--surface-elevated` (#333333) = 3.56:1 (FAIL — AA body text requires 4.5:1). Fix: changed to `--fg` (now 13.18:1). WCAG 4.1.3: dynamic error text in `oauth-modal.js` wrote into `msgEl` without a live region. Fix: added `aria-live="assertive"` + `aria-atomic="true"`. Both fixes applied inline pre-`[HANDOFF:confirmed]`. The reviewer also caught 3 non-blocking findings (deferred to routine maintenance) and 4 useful suggestions.

## What Could Be Improved

### Process

1. **L5 skipped cycle-1 design review entirely.** L5 was the largest leg by far (~2054 LOC vs ~120-330 LOC for L0-L4) AND the most architecturally novel (ContextVar binding, background-task `/api/oauth/start`, pool eviction `_evict_all_for_source`, in-process AS fixture, Playwright browser tests). Per F4 debrief KL #3 ("cycle-1 Developer review on each leg is doing real work, not gold-plating"), this skip is inconsistent with our own prior lessons. Three architectural items shipped without review: (a) the `current_chat_session_id` ContextVar with "best-effort fallback to most-recently-active session" silent-drop behavior; (b) the `_drive_flow` background task that swallows errors silently (no `httpx.ConnectError` / timeout handling); (c) the `_evict_all_for_source` pool-bust pattern that ships an externally-triggered eviction path the F4 pool design didn't anticipate. **Recommendation: codify in `agentic-workflow/SKILL.md` that Flight Director CANNOT skip cycle-1 design review when (a) leg LOC > 800, OR (b) leg introduces a new public API endpoint, OR (c) leg adds a new module-level concurrency primitive. The F4 L5 doc-only skip exemption was the right call for that leg; it should not have been precedent for F5's L5.**

2. **HAT-deferral pattern repeated from F4.** F4 HAT Step 5 was deferred because the consumer (F6 `MCPToolProvider`) wasn't built. F5 L6 HAT Tier-1 was deferred because the L0-L5 commit was the natural session-close point and the in-repo OAuth fixture's full RFC-compliant implementation would itself have been ~150 LOC of additional work. The pattern: when a flight contains both "land speculative mechanism" and "verify via HAT" legs, the HAT leg is non-separable from the mechanism leg for flight-close purposes — but the flight design doesn't make this dependency explicit. **Recommendation: codify in `flight/SKILL.md` that flight design phase MUST identify any "speculative-then-HAT-verified" mechanism and either (a) bundle them into one indivisible leg, or (b) explicitly accept "landed without HAT-verified retirement" as the flight's actual close state with the residual-debt entry pre-written in the debrief template.**

3. **§11 LOC budget undercount by ~8x.** §11 estimated ~250-330 LOC for the `oauth/` package across cycle-1 + cycle-2 corrections. Actual flight surface: ~1856 LOC across `oauth/` (~963) + outside-`oauth/` touchpoints (~893: api.py +219, app.py +206, agent/core.py +125, transports +136 + 84, client.py +112, _pool.py ~10, llm/base.py +1). The §11 framing — "module placement (slim adapter layer over SDK)" — only captured the new package, not the touchpoints listed in cycle-2 L4's "Touchpoints OUTSIDE `oauth/`" addition. The user-picked Option A for L5 expanded the surface further but most of the undercount is structural to the §11 framing itself. **Recommendation: codify in `flight/SKILL.md` that §11-style "module placement" sections produce an honest table of ALL modified files (production + tests + artifacts) with per-file LOC estimates, summed to a total LOC budget. The "new package only" framing must die.**

4. **Agentic-workflow context-budget pressure during long flights.** The orchestration session ran ~10 hours of active orchestration across 6 legs, each with cycle-1 (sometimes cycle-2) reviews + implementer agents. By L5, the orchestrator was running with substantial conversation history and partial information about earlier legs. The L5 implementer agent hit an internal API error mid-execution after ~44 minutes — recoverable but it indicates the long-tail risk of multi-leg orchestration in a single session. **Recommendation: codify in `agentic-workflow/SKILL.md` a session-checkpoint pattern: after every 2 legs or every ~3 hours of orchestration, the Flight Director should explicitly checkpoint to the user (recap state, next steps, offer fresh-session continuation) rather than pressing on through the full flight. F5's last 3 legs would have benefited from a fresh session each.**

### Technical

1. **Circular import via `MCPAuthRequired` papers over real coupling.** The straightforward module-top import `from the_one.mcp.oauth.errors import MCPAuthRequired` in both `agent/core.py` and `mcp/client.py` triggers a circular chain: `agent.core → mcp.oauth.errors → mcp.oauth.__init__ → mcp.oauth.storage → db.repositories → agent.config → agent`. Resolution was lazy import inside function bodies (flight-log L4 D2). The lazy-import pattern is a working workaround but the structural fix is to break the chain at one of two points: (a) drop `storage` from `mcp/oauth/__init__.py`'s eager imports (callers explicitly import from `mcp.oauth.storage`), OR (b) make `db.repositories` not transitively import from `agent`. **Owner: F6 (which will encounter the same chain when `build_oauth_provider_for_source` is imported from the agent layer). Recommendation: F6's first refactoring task before adding new code should be the structural break of this chain.**

2. **ContextVar fallback "broadcast to most-recently-active session" silent-drops in multi-tab.** `current_chat_session_id: ContextVar[str | None]` at `app.py:209-211` is set by `_process_and_broadcast` and `_resume_paused_session` at the message-processing boundary. When a pool worker spawns outside an agent dispatch (cold-startup pre-warm via direct API), the ContextVar is None and the sentinel `"_pool_default"` is used — `_sessions.get(...)` returns None and the `auth_required` broadcast is silently dropped. This is documented as known debt (flight-log L5 A17) but the silent-drop behavior is a hidden UX gap. **Owner: F6. F6 must replace the ContextVar set point with per-tool-dispatch ContextVar binding inside `Agent._execute_tool` (with `tool_call_id` also available). This eliminates the "_pool_default" sentinel entirely.**

3. **F2-known-issue retirement still empirically unverified.** L1 ships speculatively. The caplog assertion (`assert NO "MCPClient transport close failed" WARNING during the 5-step Tier-1 HAT`) was deferred. The dispatcher-owned-stack mechanism may or may not eliminate the warning under F4-pool-routed paths in production. **Owner: F6's first HAT step. If the assertion fails, file a follow-up flight that reverts L1's `_open_*_transport_stack` helpers + dispatcher rewrite + README §3 scoping update; re-add F2-known-issue to mission Known Issues with a real diagnosis plan. Until F6 HAT runs, the F2 known-issue entry in `mission.md` should NOT be marked retired.**

4. **`/api/oauth/start` background task swallows errors silently.** `_drive_flow` at `api.py:1084-1110` runs `httpx.AsyncClient(auth=provider).post(server_url, ...)` — if the MCP server URL is unreachable (`httpx.ConnectError`) or times out, the task dies with no error surface to the chat UI. The operator clicks Connect and nothing happens. **Owner: F6 or routine maintenance. Recommendation: catch `httpx.ConnectError` / `httpx.TimeoutException` in `_drive_flow` and broadcast an `auth_failed` event to the chat session with a descriptive message.**

5. **Browser tests not executed in this container.** 6 Playwright tests in `tests/browser/test_oauth_modal_flow.py` are syntactically correct, collected by pytest, but error on `BrowserType.launch: Executable doesn't exist at /root/.cache/ms-playwright/chromium_headless_shell-1208/...`. This is a pre-existing infra gap affecting ALL `tests/browser/*.py` files (verified by running `pytest tests/browser/test_smoke.py` → same error). **Owner: routine maintenance or F6 HAT setup. Recommendation: add `playwright install chromium` to the Dockerfile or to a `make install-playwright` target.**

6. **`stop_periodic_sweep` two-level indirection is unidiomatic.** `_state.py:199-226` has `stop_periodic_sweep` (sync) returning a coroutine from `_stop_periodic_sweep()`. The F4 pool's equivalent `shutdown_drain` is a direct `async def`. **Owner: routine maintenance (low priority). Recommendation: simplify to `async def stop_periodic_sweep()` aligned with project convention.**

## Key Learnings

1. **SDK consumption is almost always the right scope reduction call** when the SDK ships the spec-compliance machinery. The cycle-1 H1 finding for F5 is the second time the pattern has paid off (M05 F2 also delegated to SDK primitives). Future flights touching specs (RFCs, JSON-Schema, OpenAPI, etc.) should default to "find the SDK that already implements this" before designing the spec layer.

2. **Stake tests against SDK body shape (`inspect.getsource` + substring assertion) catch silent SDK-upgrade breakage.** L2's `test_async_auth_flow_body_shape_pinned` is a model pattern: 6 substrings from the SDK source verified at `mcp==1.27.0`. Any upstream refactor of `async_auth_flow` body fails this test. The pattern is reusable for any subclass-with-verbatim-override scenario.

3. **§11 "module placement" sections must enumerate the FULL flight surface, not just the new package.** F5's §11 missed ~85% of the actual flight LOC. The cycle-2 L4 "Touchpoints OUTSIDE `oauth/`" addition is the right pattern but should be the default, not an afterthought. Flight design phase should produce a per-file LOC table.
