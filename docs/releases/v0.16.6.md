# v0.16.6 — Slow-starting local MCP servers

A local MCP server that takes a while to start now connects on the newest protocol it supports.

## Changed
- **"Forget tools list" is available for local-command servers.** In Library › MCP servers, a local-command server that has been tested now shows "Forget tools list" beside its status, as HTTP servers without a sign-in already did. It clears the stored tools list and what the app remembers about the server's protocol. The next Test loads them again.

## Fixed
- **A local server that is slow to start no longer gets the older protocol.** A local-command server that took more than about 10 seconds to start, such as one run through `npx`, was connected on protocol 2025-11-25 even when it supported 2026-07-28. There was no error, and the server could show fewer tools. The app now waits for the server to start, up to about 20 seconds, before it falls back.
- **The app says when it fell back.** If a local server still does not answer in time, the Server section of its editor shows a note: the connection uses an older protocol and may offer fewer tools, and pressing Test again once the server has started fixes it.

## Notes
- No database upgrade, and nothing needs to be reconfigured.
- If one of your local servers shows Protocol 2025-11-25 and you expect a newer one, press Test once after updating.
- A local server that never answers the newer-protocol check now takes about 20 seconds to connect the first two times after the app starts (it was about 10 seconds, once). After that it connects at once.
- HTTP servers are unchanged.
