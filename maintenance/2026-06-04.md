## Executive Summary

The Mission-11 connector subsystem is **functionally and security-solid**: the Security Reviewer traced inbound-message XSS, ACL enforcement, secrets masking, injection, and SSRF end-to-end and found no issues, and the suite is green (2935 passed / 4 skipped / 0 failures / 291s). What blocks "Flight Ready" is three things — a fresh batch of dependency CVEs, a cluster of WCAG Level-A accessibility defects in the new connector-editor UI, and a **third-recurrence lint/format-gate failure** whose root cause (confirmed in roundtable) is that *no enforcement gate exists* — no CI, no pre-commit hook, only manual `make` targets. None are Critical under the single-user/single-process/local posture, but seven are Action Required.

## Findings by Category

### Category 1: Security
No issues found. The Security Reviewer traced the full inbound trust boundary and reported the subsystem as solidly built and consistent with `SECURITY-MODEL.md`:
- **Inbound XSS** — attacker-influenced Discord content (`envelope.text`, `peer_name`, `preview`) renders via `textContent`/`createTextNode` and the hand-rolled `markdown.js` (DOM-construction only, `safeHref` allowlist), never `innerHTML`. The pending-approval banner (the most direct attacker→operator path) uses `textContent`.
- **ACL enforcement** — `admits_inbound` (`_acl.py:379`) is checked at *every* routing branch in `resolve_routing` (override/rule-match/default/first-eligible). No branch returns an agent unchecked.
- **Secrets** — Discord `BOT_TOKEN`/`application_id` are Fernet-encrypted at rest; all four connector read paths route through `_connector_response` masking (`__MASKED__` sentinel); tokens never logged.
- **Injection / SSRF** — SQL parameterized; no shell in the send path; Discord host hardcoded (no operator/attacker URL surface).

## Delegation Effectiveness Notes

For refining future inspections of this project:
- **Two-wave module-partitioned Inspector was the right call for a large changeset on a medium project.** The 91-file / 28k-insertion M11 surface would have overwhelmed a single Inspector context. Partitioning by module boundary (connectors / interfaces / db+backend) with a separate tool-pass agent kept every agent well within context and produced non-overlapping findings. Use this shape whenever a "recent changes" scope exceeds ~50 changed files.
- **Pre-loading known debt as "mark previously-identified" worked** — reviewers correctly distinguished the deferred architectural cluster from new M11 issues and added value by *characterizing current state* (e.g. confirming `_acl.py` grew, root-causing the aiosqlite warnings) rather than re-alarming.
- **Roundtable earned its keep this cycle** (unlike 2026-05-15, where it was skipped). All three challenges resolved to actionable reframings: Q1's fix-the-gate-not-the-format (confirmed zero CI/hooks), A1's downgrade with A2 held as the operability priority, and I1's idempotency verification (per-row guard co-granular with per-row commit). Reserve it for findings where the *disposition* or *severity calibration* is genuinely contestable — not factual disputes.
- **The highest-leverage finding was again a gate-enforcement inference, not a raw count** (Q1) — mirroring 2026-05-15. Continue explicitly tasking the tool-pass Inspector with checking whether prior-pass-introduced gates are still *enforcing*, not merely present.

## Recommendations

1. **Land the maintenance mission ([12-maintenance](../missions/12-maintenance/mission.md))** — 6 flights, scoped to land in a focused cycle.
2. **Flight B (the lint/format gate) is the highest-leverage item** — install a pre-commit hook + a CI `ruff check` + `ruff format --check` step that *fails* on violations, with the 78+97 cleanup as a one-time side effect. Without the gate this is the fourth recurrence next cycle. There is no CI today, so this is greenfield.
3. **Ship the dependency CVE bump (Flight A) first** — smallest, highest-certainty win; network-facing libs warrant it even local.
4. **Treat the connector error-handling fixes (Flight C) as one theme** — T2/T1/Q2 are all "the error taxonomy isn't actually wired through." Remove the `noqa: BLE001` crutch as part of T2.
5. **The a11y pass (Flight D) is one cohesive session over `connector-editor.js` / `connectors-tab.js` / `connector-form-discord.js`** — A2 first (keyboard reorder), then A3/A1/A4/A5, opportunistically A6/A7.
6. **Port the PTY reaper to web `_sessions` (Flight E)** — the one architectural item single-user does not bound; a copyable pattern already exists in-repo.
7. **Flag Q6 (`_acl.py` extraction) for the next ACL-touching flight's prerequisites** — do not let it land on an 809-LOC monolith.
