# v0.12.2 — Safe names and a rebuilt MCP server editor

Names can no longer break an agent, a model provider, a knowledge base or an MCP server, and the MCP server editor has been rebuilt.

## Fixed
- An agent whose name contained a `/` could not be opened, edited, renamed or deleted, and its editor said "Couldn't load this agent's current configuration". Names for agents, model providers, knowledge bases and MCP servers now can't contain `/` or `\` or control characters, can't be just `.` or `..`, and can be at most 64 characters. If a name breaks these rules, the form tells you so on the Name field.
- Creating an agent with the same name as an existing one no longer replaces that agent. The form tells you the name is taken.
- Renaming an agent keeps the connectors that point at it. Renaming an MCP server keeps each agent's settings and turned-off tools for that server.
- When an agent's settings can't be loaded, a message now tells you, and a note next to the disabled Save says why it is off.
- In the MCP server editor, saving no longer loses or reveals stored secrets, clicking Create twice no longer creates two servers, and the sign-in wait stops when you leave the editor.

## Changed
- The MCP server editor has been rebuilt. Environment variables and request headers are edited in a table where secret values stay hidden and each entry can be switched on or off. A connection error shows a short headline, with the full message under "Technical details".

## Notes
- The first time the app starts after the upgrade, it renames any existing agent, model provider, knowledge base or MCP server whose name breaks the new rules. A `/` or `\` becomes a space, and a number is added if the new name is already taken. Everything attached to the item stays attached, and each rename is written to the app log. An agent named `default` is left as it is.
