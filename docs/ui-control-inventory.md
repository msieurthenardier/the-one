# UI control inventory

The app-wide classification of every control kind: which ones the `App.ui` control
library defines (M25 F1 L6, DD11; every row is a library control since M31 F6 L09a, and retired ones
are in "Retired controls"). The library is
documented in `the_one/agents.md` ("Control library (`App.ui`)"); its reference is this
catalogue plus each factory's engine-parametrized contract tests
(`tests/browser/test_ui_*.py`). The colour, spacing and type tokens are listed in "Tokens
and type" at the end.

## The guard and how to update this file

`tests/test_ui_control_inventory.py` (unit tier) reads every `App.ui.<name> = function`
export in `the_one/interfaces/web/static/js/ui/*.js` (`App.ui.util.*` excluded) and
checks both directions against this file:

- every factory appears here as `App.ui.<name>` (a missing row fails);
- every `App.ui.<name>` cited here is a real factory (a stale citation fails).

The same file also requires a contract test for every factory: each name must be called as
`App.ui.<name>(` in at least one `tests/browser/test_ui_*.py` file
(`test_every_factory_has_a_contract_test`). The row checks read only the control tables
(tables whose header line starts `| Control |`): each row has six cells, a status that is
`library: App.ui.<factory>`, and at least one owned class.

The **Owned classes** column (M31 F1 L2, DD3) is the list the reuse check
(`tests/test_ui_ownership.py`) reads: an owned class token outside `js/ui/` is a failure (the
allowance tables are empty and stay empty).

When you add a factory: add its row here and its contract tests (see "Adding a factory" in
`agents.md`). A row's status is `library: App.ui.<factory>`; `test_no_control_row_is_not_yet_defined`
fails on any other. A control that is removed moves to "Retired controls".

Paths below are relative to `the_one/interfaces/web/static/`.

The provider editor and its models section hold their handles through slots.

- **`App.ui.util.syncChildren(parent, nodes, {after})`** (M31 F4 L03b; a helper, not a control): reconciles the element children of `parent` after the optional `after` anchor (all of them without one) to exactly `nodes`, in order. A child not in `nodes` is removed first, then a node is inserted only when it is not already at its position, so a node already in place is never re-inserted (moving an attached node blurs a focused descendant) and siblings up to the anchor are untouched. Element-only; throws on a non-element, a duplicate, an anchor outside `parent` or a node sitting before the anchor; a node living in another parent is moved in. Callers keep their own `.filter(Boolean)`. The one copy: the knowledge folders and rows modules and the provider models panel use it.
- **`App.ui.util.latest()`** (M31 F4 L03a; a helper, not a control): "latest request wins". `{next() -> token, isCurrent(token), invalidate()}`; `next()` makes every earlier token stale, `invalidate()` makes every token stale (a teardown), and two helpers are independent. Tokens are opaque: callers only pass them back to `isCurrent`.
- **`App.ui.util.middleEllipsis(value, budget)`** (M31 F4 L04e; a helper, not a control): a value of at most `budget` characters comes back unchanged; a longer one keeps its first `round((budget - 1) * 0.6)` and last remaining characters around one "…", exactly `budget` long (40 gives 23 + "…" + 16).
