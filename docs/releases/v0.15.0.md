# v0.15.0 — Secrets: use a password without showing it to the agent

Store a password, key or personal detail once in the Library, grant it to the agents that need it, and they can use it in tool calls without the value ever appearing in a chat, in tool activity or in a request to your model provider.

## Added
- **Library › Secrets.** A new group in the Library, with its own entry in the Add menu and on the Library start page.
  - A secret has a name, a description and one or more key/value pairs, such as an address with a street, a town and a postcode.
  - The first key is generated from the name. **+ Add pair** adds more.
  - Values are stored encrypted and are never shown again. Agents see the name, description and keys, never the values.
  - Each secret has a required **Allowed tools** list, with search-ahead over built-in and MCP tools. The secret can only be used in those tools.
  - Deleting a secret removes it from every agent it was granted to.
- **Grant a secret to an agent** from the new Secrets section at the top of the agent's Tools tab. The chat drawer lists the secrets an agent has, and Settings › Prompts shows what agents are told about them.
- **Agents use secrets with a placeholder.** The agent writes `{{secret:key}}` in a tool argument, and the app fills in the real value only at the moment the tool runs. The saved chat, the tool activity and the requests sent to the model provider show only the placeholder.
- **Output is masked too.** If a tool's result or error contains a stored value, the agent and the saved chat see `[secret:key]` instead.
- **A secret is refused where it was not allowed.** An agent cannot use a secret it was not granted, or use one in a tool that is not on that secret's allowed list. The error names the key and never the value.
- **Library changes apply on the agent's next tool call**, including in a chat that is already open: a new value, a removed grant or an edited allowed list. There is no need to start a new chat.
- Tools that store or publish what they are given cannot be allowed for a secret: notes, routines, posting to a platform channel and self-configuration.

## Notes
- The database is upgraded automatically (schema 50 to 51). Nothing needs to be reconfigured.
- Secrets already pasted into an agent's system prompt are not moved for you. Add them to the Library by hand, grant them, and remove them from the prompt.
- Masking matches the exact text. A tool that changes a value (for example by base64-encoding it) is not masked. A very short value, such as a postcode, may also hide unrelated text that happens to match it.
- Allow a secret only in tools you trust with it. The tool receives the real value.
- Encryption-key rotation covers secrets.
