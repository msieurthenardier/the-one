# Leg: oauth-callback-reachability

**Status**: completed
**Flight**: [Credential lifecycle integrity and observability](../flight.md)

## Objective
Prove — with a failing test first — that the external-IdP OAuth callback (`GET /api/oauth/callback`) cannot complete through the credential gate on a cross-site redirect today, then exempt that one state-guarded path from the gate (flight Design Decision Q3), re-confirming in the diff that the handler mints nothing and is replay-safe, and pin the behavior with a middleware-inclusive unit test and a genuine cross-site browser-lane test.

## Context
- **Flight Design Decision Q3**: exempt `GET /api/oauth/callback` — second entry in `EXEMPT_PATHS` beside `GET /api/live`. Cookie stays `SameSite=Strict`. `SECURITY-MODEL.md`'s "exactly one exemption" becomes two.
- **Why it fails today**: `CredentialGateMiddleware._handle_http` (`middleware.py:~309-312`) admits only `path in EXEMPT_PATHS` (`frozenset({LIVENESS_PATH})`, `middleware.py:185-186`) before resolving the cookie or `Authorization` header. The session cookie is `HttpOnly; SameSite=Strict` (`middleware.py:247`), and browsers withhold a `Strict` cookie on any cross-site top-level navigation — which is exactly what the IdP's redirect back to `/api/oauth/callback?code=…&state=…` is. So the gate 401s before `oauth_state.resolve` runs and the pending flow times out. Nothing notices: `tests/test_oauth_callback_route.py` builds a bare `FastAPI()` + `router` with no middleware.
- **What the handler does** (`api.py:oauth_callback`, `api.py:~2999-3150`): 401 on missing `state`; `peek(state)` → 401 on unknown; on `error` → `fail` + broadcast `auth_failed` + HTML "Login failed"; else `resolve(state, code, state)` (pops the entry; `False` if the TTL sweep raced → HTML "Login expired"); on success broadcast `auth_resolved`, schedule resume, HTML "Login successful. You may close this tab." It reads no DB, writes no DB row, mints no credential, sets no cookie. A replay of a consumed `state` hits `peek → None → 401`. The `state` token is SDK-generated, URL-safe random, single-use — it is the credential for this one path.
- **Why not the alternatives** (from the flight): relaxing the cookie to `Lax` reopens the M20 GET-side rebinding decision (`middleware.py:232-235`); a `postMessage` relay still needs the callback page itself to load unauthenticated, so it needs the exemption anyway. Note the callback page *already* `postMessage`s an `mcp-oauth-result` to its opener (`_render_oauth_callback_page(post_message=…)`) — that is unaffected.
- **Method scope**: `EXEMPT_PATHS` is path-only (no method check, `middleware.py:310`); the M20 rationale at `middleware.py:~178-184` is that the exempt route is registered GET-only so other methods 405 at routing. The same holds here — `@router.get("/oauth/callback")` only — and the unit test pins it (`POST` → 405, not 200/401-from-handler).
- **Cross-site verification without an IdP**: `localhost` and `127.0.0.1` are different sites. The browser lane spawns the app on `http://127.0.0.1:<port>` (`tests/browser/conftest.py:_spawn_app`, `:248`) with `THE_ONE_DEV_MODE=true` (`:216`), and the `page` fixture's wrapped `goto` establishes a session cookie per origin via the handoff exchange (`conftest.py:412-480`). The Origin allowlist accepts both hosts on any port (`middleware.py:163-164`). A raw page in the same context that first loads a `localhost` document and then top-level-navigates (`window.location.assign`) to the `127.0.0.1` callback URL is a cross-site navigation whose initiator is another site — the browser withholds the `Strict` cookie exactly as it does after an IdP redirect. A control navigation to a gated route (`/api/info`) the same way must 401, proving the cookie really was withheld.
- **Seeding a pending flow in the subprocess app**: only in-process `_state.register` can create one (`the_one/mcp/oauth/_state.py:68`). Precedent for a dev-mode-only test seam exists: `POST /api/_test/…` routes gated by `settings.dev_mode` → 403 (`api.py:~4558-4600`, `seed_routing_audit`; `lookup_chat_session`). Add one more, same gate.
- **Prior-leg learnings**: Leg 1 and Leg 2 both edit `api.py`; re-verify line numbers against the landed tree (Citation Audit). Leg 2 adds `request: Request` to routes — do not touch those.

## Edge Cases
- **`HEAD /api/oauth/callback`**: FastAPI answers `GET` routes to `HEAD` — harmless (same inert handler). No test needed.
- **Trailing slash / case**: `EXEMPT_PATHS` is exact-match; `/api/oauth/callback/` stays gated. Fine — the IdP redirects to the exact registered URI.
- **`state` present but flow expired by the sweep between `peek` and `resolve`**: "Login expired" 200 page — unchanged, still inert.
- **Playwright popup-blocking / auto-close**: the callback page auto-closes ~1.2s after paint on success; read `raw.content()` immediately after navigation or assert on the response body via `expect_navigation`. If the tab closes before the assertion, assert on the navigation response text instead.
- **Browser test without dev mode**: seam 403 → the test must fail loudly, not skip. `app_clean` sets the env; do not add a skip.
- **Origin allowlist on the cross-site hop**: `OriginAllowlistMiddleware` gates only `POST/PUT/PATCH/DELETE` (`GATED_METHODS`, `middleware.py:~80`), so a top-level GET navigation — with or without an `Origin` header — passes. Confirmed in design review; no finding here.
- **Why the cookie is withheld**: not merely because `localhost` ≠ `127.0.0.1` — a `Lax` cookie *would* be sent on a cross-site top-level GET. It is specifically `SameSite=Strict` (`middleware.py:232-247`) that withholds it, which is why the negative control (`/api/info` → 401 cross-site, → 200 same-site) is the proof the leg needs.
