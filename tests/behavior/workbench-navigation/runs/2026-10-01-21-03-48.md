## Orchestrator Notes

- **Mode and approach:**
  - Live mode: SendMessage continuation, with the Executor and Validator persistent within each variant.
  - Cache mode: cold.
  - The Dark Executor was replaced for Light because of its context size and the apparatus change. The Validator persisted.
- **Pipelining (Light only).** After L3, the next checkpoint's Actions were sent to the Executor while the Validator judged the previous one.
  - This was safe because every Light checkpoint carried file-based rendered evidence (PNG plus aria).
  - The Validator never needed a live re-observation.
- **Goldfinch input outage (apparatus).** After the Dark variant, goldfinch stopped delivering synthetic input on this host.
  - `click` and `pressKey` return ok, but capture-phase listeners recorded zero events. This affected fresh tabs 61 and 62.
  - The Orchestrator reproduced it.
  - Navigation, `evaluate`, `readAxTree` and `printToPDF` still worked.
  - The viewport changed from 1400×782 to 1400×900 at the same time.
  - `enumerateWindows` and `captureWindow` are admin-only, so the cause could not be diagnosed. A window overlay is suspected.
- **Apparatus deviation (Light).** The Light variant was driven by headless Chromium 147 (Playwright `chromium-1217`) over CDP at `127.0.0.1:9333`.
  - Playwright `connect_over_cdp` was used per step, with real input events, `page.screenshot` and aria snapshots.
  - `browser.new_context()` over CDP is disposed on disconnect. The persistent context was therefore created with raw CDP `Target.createBrowserContext` (`disposeOnDetach:false`), and the page was found by `window.name`.
  - The spec's Preconditions name goldfinch. This substitution is recorded as a deviation; the observables are identical.
- **Theme control.** The spec's Variants section says `aria-pressed`, but the build's theme control is a radiogroup (`role=radio`, `aria-checked`). `aria-checked` was used.
- **D11 lost first keystrokes.** The Flight Director first suspected an app race (the editor re-rendering after the fresh-agent fetch). This was falsified by the D13r and L11 MutationObserver probes, which saw no field replacement even when typing 59 ms after mount.
- **Stale asset cache (squawk 0085).** On the first Dark load, a disk-cached `icons.js?v=0.9.1` without the `database` icon made `mountRail()` throw, leaving an empty shell. The Executor fixed it with `fetch(cache:'reload')` on every asset, then a reload, before step 2.
- **Retracted Flight Director claim.** Mid-run, the Flight Director said step 11's cold reload makes step 13's Back cross-document. L13 Part A disproved this in Chromium. The spec's step 11/13 design is sound. D13's first attempt failed only because of the D10 probe.
- **Product observations (not failures):**
  - The Connectors empty-state "New Connector" button renders unstyled. `connector-editor.js` builds it as `_btn('empty-canvas-cta', …)` without the `btn-outlined-primary` class the MCP grid uses. It predates Flight 2, and is an input for Flight 3, which rebuilds the Library lists.
  - Section-nav items are `<button>`s with `aria-current`; the rail uses links. This predates Flight 2 (`section-nav.js`) and is an input for Flight 3's Library and Settings navigation.
  - A cross-document Back with a dirty editor is silently blocked by `beforeunload` in goldfinch (Electron).
