# Behavior Test: Shell Navigation Smoke

**Slug**: `shell-navigation-smoke`
**Status**: active
**Created**: 2026-07-03
**Updated**: 2026-10-05 (M25 F3: the Agents list, the Library groups; Providers as tiles, leg 7. M25 F4 leg 8: step 1's Jump to control, step 3 re-authored for the Chats list, the chat pane and the empty and guidance states)
**Last Run**: 2026-10-05-14-53-19 — pass (8/8; re-run after M25 F3 leg 7, Providers tiles)

## Intent

Verify that the app shell's core navigation contract holds against the running instance: the left rail offers four destinations (Chats, Agents, Library, Settings) and each renders when selected, the theme switcher (Settings › Appearance) visibly changes and restores the theme, a cold deep link survives a reload for both a current route (`#settings/providers`) and a legacy route (`#admin/providers`, which must redirect), and no destination renders an error state. This is deliberately data-independent (passes on any database state) and strictly read-only with respect to server data — designed as a re-runnable gate for the UI mission series, where every flight churns markup and this contract must keep holding. A behavior test (not a Playwright test) because it verifies the *operator's live instance* through a real browser apparatus with rendered-state evidence, exactly the surface the redesign changes. The deeper navigation behaviors (Back, rail restore, leave guard) need seeded data and live in `workbench-navigation`.

## Preconditions

- The **instance under test** is running and serving (probe: HTTP 200 on `/` immediately before the run). Default `http://127.0.0.1:8485` — a dedicated dev instance with a scratch data directory; the operator's packaged app owns `:8484` and must never be targeted (see CLAUDE.md's "Behavior-test credential convention" safety rule). The orchestrator states the actual base URL at run time and it applies to every step below.
- A browser apparatus is attached and can open tabs to that origin: goldfinch MCP, or a CDP/Playwright-driven Chromium using real input events.
- **Credential**: this instance is gated (Mission 20 Flight 1). Follow CLAUDE.md's
  "Behavior-test credential convention" — read the long-lived credential from the
  instance's data directory and mint a handoff URL for the Step-1 navigation
  (single-use; re-mint if navigating again, e.g. after the Step-8 or Step-9 cold reload if the
  session cookie was lost).
- Existing data is acceptable — every step accepts both populated and empty states explicitly; no seeding is performed by the test.
- Evidence note: goldfinch screenshots have been unavailable on some hosts (display surface not available for capture). When a screenshot fails, the sanctioned evidence is `printToPDF` plus the accessibility tree plus computed-style evals (background/foreground colours, `data-theme`); the report states which path was used.
- Run-tab environment: prefer an unoccluded/foregrounded window; if pixel capture wedges, the printToPDF fallback per the apparatus doctrine (`the_one/agents.md`) is sanctioned evidence.

## Observables Required

- browser (rendered page state, screenshots, DOM/a11y state — measured via goldfinch MCP)

## Out of Scope

- CRUD flows (agent/provider create-edit-delete) — covered by Playwright browser tests and the seeded behavior specs (`studio-agent-crud`, `system-provider-config`).
- Back/forward stepping, rail restore of the last-open item and the unsaved-changes leave guard — need seeded data; covered by `workbench-navigation`.
- Chat message round-trips and streaming — a dedicated chat behavior spec (M17 Flight 7) covers those with a mock provider.
- Starting a chat (the agent picker, the pending chat, the agent drawer) — `start-a-chat`; the Jump-to palette — `jump-to-palette`.
- Accessibility depth (keyboard operability, ARIA) — covered by per-leg a11y gates.
- Visual regression against baselines — pixel snapshots (local-only) cover that.
