# v0.16.0 — Charts and live widgets in chat

Agents can now answer with a picture: a chart drawn in the reply, or a small live widget that runs inside it. Charts also reach Discord and Telegram as images.

## Added
- **Charts in replies.** An agent can include a bar, line, area, scatter or pie chart, or a sparkline, and the chat draws it in place.
  - Charts follow the light and dark theme, including a theme change while the chat is open.
  - **Show data** opens the chart's values as a table. Each chart also has a text description for screen readers.
  - While a chart is still being written, the reply shows a "Rendering" placeholder. When it is ready the chart appears.
  - A chart the app cannot draw shows a plain error, with the original block under **Technical details**.
- **Live widgets in replies.** An agent can include a small animation, simulation or interactive widget, and it runs inside the reply.
  - A widget is walled off. It cannot use the network, see or change anything in the app, or open windows.
  - Widgets run while they are in view and pause when scrolled off screen. A long chat keeps at most 3 widgets running and 8 loaded.
  - Each widget has a **Pause** / **Resume** control.
  - A widget that stops responding is stopped and shows a notice, so it does not freeze the app.
- **A "Rich visuals" switch on each agent.** It is in the General tab's Behavior section, on by default for new and existing agents. Turn it off for an agent that should not be told how to write charts and widgets. A change reaches a running chat the next time the chat is joined. The chat drawer shows the setting.
- **Charts on Discord and Telegram.** A chart in a reply is sent as an image, with a line marking where it belongs and the chart's title as the caption. The same applies when an agent posts with `send_to_platform_channel`.
  - A widget cannot run on a platform, so it is replaced by a short note that points to the app.
  - If a chart image cannot be drawn or sent, the chart's own text block is sent instead.
  - The stored chat is unchanged, so the app still shows the real chart or widget.
- **`the-one doctor` has a new "chart images" check.** It confirms the chart image drawing works on this install.

## Changed
- **Agents with Rich visuals on are told how to write charts and widgets.** This adds a section to the system prompt, shown in Settings › Prompts, and the prompt is somewhat larger. Turn the switch off for an agent to leave it out.
- **Copy reply still copies the original text**, including a chart's or widget's source, not the picture.
- **The desktop app's window no longer exposes its internal native bridge to page content** on Linux and macOS, so a widget frame cannot reach it. Nothing in the app used it.

## Notes
- The database is upgraded automatically (schema 51 to 52). Nothing needs to be reconfigured.
- Pillow is now a base dependency, used to draw chart images. A source install picks it up with `pip install -e .`. The packaged apps already include it.
- Widgets only run in the app (the desktop window or the browser), never on Discord or Telegram.
- The Rich visuals switch only decides whether an agent is told how to write visuals. A chart or widget in any reply is still converted for Discord and Telegram, whatever the switch says.
- Chart images on platforms are checked against local test stand-ins, not live Discord and Telegram, so how a platform displays one is up to the platform.
- Chart images cannot draw CJK text or emoji (they show as boxes). A chart's title still goes out as text.
- A chart or widget inside a quote or a list stays as text on platforms.
- Small local models rarely write a working widget. Widgets work best with Claude-class models.
- Widgets are model-written code running in a sandbox. SECURITY-MODEL.md, "Live visuals", describes the boundary and what remains.
