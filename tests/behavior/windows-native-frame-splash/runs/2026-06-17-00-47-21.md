## Fix History (HAT-caught, this run)

The HAT caught three real defects the host-native unit tests had missed (DD6/DD7 value):

1. **Splash hung forever (build #18→#19, commit `c61d220`).** `_boot(splash_win)` was defined
   with a parameter, but pywebview's `webview.start(_boot)` calls it with no args → the boot
   thread crashed (TypeError, confirmed in the crash log) and the main window never opened. The
   unit tests masked it by invoking `_boot(mock_splash)` (the buggy signature). Fixed: `_boot()`
   no-arg + closure `splash`; proactively closed a `loaded`-event race; tests now call `_boot()`
   the way pywebview does. Also added the README logo to the splash.
2. **Window-chrome controls didn't render (build #19→#20, commit `34a4e8d`).** The main window
   is the 2nd window (created post-`start` from `_boot`); pywebview's `pywebviewready` fired
   before app.js's listener attached, and a missed `CustomEvent` never retries. Fixed with a
   `_watchBridge` poll backstop.
3. **Frameless chrome fundamentally fought WebView2 (build #20 → DD3 divert, commit `e266d28`).**
   Even with controls rendered, the `js_api` buttons didn't fire and titlebar drag/resize were
   dead — pywebview's frameless drag (`easy_drag`/`.pywebview-drag-region`) only activates on
   `platform=='chromium'`, not Windows `'edgechromium'`; CSS `app-region` is Electron-only.
   **Operator decision: DD3 divert → DD2-alt (themed native frame).** Reverted to `frameless=False`
   (the F4/F6 known-good window), removed the frameless custom chrome, kept the splash + brand
   icon. Build #22 passed all 10 steps.

## Orchestrator Notes

- Native window behavior has no CI proxy (DD6); the HAT was the only apparatus that could surface
  defects 1–3. The unit/Playwright tests stubbed pywebview (bridge always present at script-eval),
  so they could not reproduce the real WebView2 injection timing or the frameless/WebView2
  incompatibility — exactly the DD7 hazard.
- A throwaway dev-python diagnostic (two-window pywebview repro + `debug=True` devtools, loading
  the real served UI) gave ground truth that the bridge *is* injected into a 2nd window — which
  redirected the investigation from "bridge missing" to "frameless chrome incompatible with
  WebView2", leading to the divert.
