# v0.11.5 — MCP servers on the newest protocol

MCP servers on the newest protocol (2026-07-28) now connect on it, and the MCP editor shows the protocol each server is using. Servers on older protocols keep working with nothing to change, sign-in included.

## Added
- The-one tries MCP protocol 2026-07-28 first, then falls back to an older one on its own. A server's details line in the MCP editor shows the protocol it agreed on.
- After the first connection in a session, an older server connects with no extra delay.
- A server that only speaks 2026-07-28 can now be tested and signed in to from the MCP editor.

## Changed
- The MCP client now runs on version 2.3.0 of the official `mcp` SDK.
- Remote MCP servers and their sign-in now check TLS certificates against your operating system's certificate store. The `SSL_CERT_FILE` and `SSL_CERT_DIR` settings override it.
- Four MCP cases now show a plain one-line error:
  - a single streamed server message over 1 MiB;
  - a redirect to a different site;
  - a sign-in server that doesn't identify itself as the expected one;
  - a lost session on a server that keeps no session state.
- When Test connection finds a stored sign-in no longer works, it now clears it before offering a fresh sign-in.

## Fixed
- The MCP editor now waits up to 2 minutes for you to finish signing in. Before, it gave up after 15 seconds.
- A tool that asks for input the-one can't provide now gives a plain one-line error. Before, it passed a raw SDK error to the agent.
- A server that requires sign-in and speaks only the newest protocol now shows a sign-in prompt. Before, it failed with a generic connection error.

## Notes
- `the-one doctor` has a new check, `mcp sdk`.
- Older MCP servers are unaffected. If one misbehaves after this upgrade, Reset connection on it starts the protocol check again.
