## Orchestrator Notes

- **Apparatus**: chrome-devtools MCP was used (NOT goldfinch), per the run mandate and the F5 lesson — goldfinch wedges on multi-step seed+drive flows, cannot observe `:focus`, and lacks an `ignoreCache` reload. chrome-devtools held real window focus (foregrounded via `select_page bringToFront:true` before every capture) and wrote full-color rendered screenshots. A single shared driving tab (pageId 23 on `http://127.0.0.1:8485`) persisted across all spawns; port 8484 was never touched.
- **Execution mode**: re-spawn-per-checkpoint with synchronous crew. Every Executor and Validator was spawned `run_in_background:false` so each report returned directly to the Orchestrator (no orphaned background crew). Executor and Validator were always separate agents (Witnessed independence). Rendered-state evidence (screenshot + a11y snapshot) was saved to the ephemeral evidence dir and Validators read those files directly to satisfy the evidence-for-pass rule.
- **Pre-run cleanup**: Listed `/api/providers` before the run — only legitimate providers present (Anthropic, Ollama Local); no orphaned test artifacts (no test/behave/crud/roundtrip/mock fixtures from prior a62c gate runs). Nothing to delete. Dev-mode precondition verified: `/api/providers/types` includes `{"value":"mock",...}`.
- **Theme handling**: original operator theme preference was `null` (unset → default light). Orchestrator set `theme-preference=light` for the light variant and `theme-preference=dark` for the dark variant (localStorage + ignoreCache reload flips `data-theme`), and restored the original unset state on teardown (verified `localStorage.getItem('theme-preference')===null`, `data-theme=light`).
- **Anomaly 1 — armed-delete capture timing (light CP9)**: the armed "Confirm Delete?" flip is gated by an async agent-usage pre-check (`GET /api/providers/{id}/agents`) and auto-reverts after ~3s. The first light-CP9 Executor captured before the async gate resolved (caught the unarmed "Delete Provider" label). This is an apparatus/timing artifact, not a product fault (provider was never deleted). Rerun with corrected timing (poll the button label within the revert window) captured the armed state cleanly → PASS. To photograph the transient state without racing the ~3s revert, Executors paused only the long (>=1500ms) auto-revert `setTimeout`; this did not alter the two-step delete semantics and did not delete anything (API confirmed the provider still present at 200 during capture). Dark CP9 flipped on the first poll (gate resolved fast) and needed no rerun.
- **Anomaly 2 — H1 header/Name-field desync (light + dark CP7, advisory, out of scope)**: after editing and saving the provider Name, the editor's H1 heading did not re-render to the new name while the Name input correctly persisted the edited value. Reproduces in both themes (theme-independent). Outside CP7's Expected Result (which scopes persistence to the field), so it did not affect any verdict — flagged here for the flight owner as a minor UI consistency defect.
- **Specialized validators**: the Accessibility Validator is disabled in the project crew file (`Enabled: false`); the base Validator judged the [a11y]-marked CP9 rows with a11y-weighted criteria (visible label + accessible name flip + armed styling + not-deleted) per the Validator brief. No separate Accessibility Validator was spawned.
