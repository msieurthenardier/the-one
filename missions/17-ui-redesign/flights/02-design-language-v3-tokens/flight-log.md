## Anomalies

- **Stale packaged app squats on 8484**: `the-one-app.exe` (Windows PID 342988, running since before this flight) binds 127.0.0.1:8484 and serves an old bundled build. **`make up`/`make restart` reports success while the fresh server actually dies with `[Errno 98] address already in use`** — `verify-serving` then green-lights against the FOREIGN server (its module URLs 200), which silently masks the bind failure. Any 8484-based visual check would render pre-v3 CSS. Worth a follow-up: `verify-serving` (or `up`) should assert the served instance is the repo build (e.g. version/mtime probe). Operator may also want to quit the tray instance.
- tokens.css at HEAD had CRLF-looking artifacts in served values (`\r\n` inside computed custom properties from the old build) — gone with the v3 rewrite (LF only).
- **(Leg 2a) Backgrounded-tab frozen transitions poison computed-style probes**: after `App.theme.set('dark')` in a backgrounded goldfinch tab, elements whose rules `transition: background-color` (`.entity-tile`, button primitives) kept computing the LIGHT theme's colors — the tab's rendering is throttled, so the 250ms transition never advances past its FROM state, while `var(--accent)` on the same element already resolved to the dark value. Foregrounding the tab (printToPDF's foreground-first side effect) unfreezes it instantly. Apparatus rule: **foreground the tab (or re-probe after a printToPDF) before trusting computed colors taken after a theme flip**. Worth folding into the Leg 3/agents.md apparatus doctrine.
- **(Leg 2a) Versioned-stylesheet cache masks fresh CSS after `make restart`**: the SPA links assets as `?v=0.2.15`; the browser serves the cached versioned response even after the server restarts with new CSS. First probe after restart showed pre-sweep styles. Fix: `fetch(href, {cache:'reload'})` over `document.styleSheets`/`document.scripts` then `location.reload()`. Same doctrine-worthy note.
- **(Leg 2a) `captureScreenshot` wedged again** (timeouts, same as Leg 1) → printToPDF fallback + computed-style probes per the established apparatus doctrine; print emulation drops background colors, so computed-style probes remain the primary color evidence.
- **(Leg 2b) `captureScreenshot` wedged a third time** (timeout on first call) → printToPDF fallback + computed-style probes, per doctrine. Three-for-three across legs — the Leg 3 apparatus-doctrine write-up should treat printToPDF+computed-style as the default evidence path for this environment, not a fallback.
- **(Leg 4) `captureScreenshot` wedged a fourth consecutive time** (timeout on first call) — the doctrine's default-path ruling stands confirmed.
- **(Leg 4) goldfinch window never holds OS focus in this environment** (`document.hasFocus()` false in every probe): `:focus`/`:focus-visible` states are structurally unobservable via goldfinch — synthetic Tab keypresses move `document.activeElement` but no focus pseudo-class matches. Doctrine-worthy addendum: judge focus-state rendering via a CDP-driven page (or Playwright), not goldfinch.
- **(Leg 4) Six pixel-snapshot baselines were root-owned** (`tests/browser/__snapshots__/*.png` dated May 15, `root:root`) — a historical test run executed as root; `--snapshot-update` fails with `PermissionError` on overwrite.
