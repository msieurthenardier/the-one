### Methodology debt observed in this run (worth banking if recurring)

- **Spec-example questions tied to specific model behavior** (step 7): a spec example that's reasonably rejected by the gate's model isn't a spec problem per se, but the spec should either pre-validate examples against the configured model OR explicitly note that the test harness may substitute equivalent questions if rejected.
- **Slate composer apparatus quirks** (steps 4, 7, 9): only `ClipboardEvent` paste + `press_key Enter` reliably sends in the Discord composer; `fill` and `type_text` silently break. The discipline was eventually established mid-run and held through all later Discord steps. Apparatus-tactic territory, not spec territory.
- **Mid-iteration text-verification anti-pattern**: re-pasting on apparent paste failure concatenates content because Slate consumes the event into its internal model that doesn't surface in `textContent`. Discipline: one paste, no verification, then Enter.
- **Provider-switch corruption of stored history**: switching an agent's provider mid-session can leave the existing chat session unsendable. Documented as #25; for now operator can mitigate by resetting affected sessions after a provider switch.
