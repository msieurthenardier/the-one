## Executive Summary

Underlying posture is healthy: every M06 F1 security control held (Origin allowlist, https-refusal, encrypted-at-rest credentials, `SECURITY-MODEL.md`); MCP module (M07's ~4,444 LOC new surface) has dense test coverage (~10,909 LOC of MCP/OAuth tests, 2.5:1 ratio); F5 L01.5's broad-pytest fix is structurally idempotent for CI; A.1/A.2/A.3/A.4/A.5/A.8 accessibility fixes from M06 F1 + later flights are intact and confirmed. 0 critical, 12 Action Required, 22 Advisory, 1 Pass.

What surfaced is "the integrity gate posture M06 established was silently eroded across M07 and M08." Three concrete signals: (1) `ruff check` baseline regressed from 0 → 69 errors; (2) `ruff format --check` regressed from 0 → 81 files would-reformat (including 9 core MCP files); (3) dev-extra `asgi-lifespan` is declared in `pyproject.toml` but not installed in the working venv, masking 6 MCP HTTP integration tests at collection time. The CI gate at `ci/pipeline.yml:24` is `&&`-chained and should have fail-fast caught (1)+(2) — it didn't, so either CI never ran against the M07/M08 branches or the gate is being bypassed. The maintenance mission's framing is: "restore the integrity gate posture M06 codified, prove via deliberate-violation experiment that the pipeline rejects."

One genuine new security finding sits in M07's new attack surface: the OAuth callback page renders `json.dumps(post_message)` directly inside a `<script>` body without HTML-escaping `</`, so a malicious-or-compromised third-party OAuth Authorization Server can inject same-origin script that bypasses the Origin allowlist (Architect escalated from Reviewer's "medium under operator-trusted" to Action Required — `SECURITY-MODEL.md` "Future Work" names the MCP trust-boundary gap as a gap to close, not a license to ship exploitable code within it). One-line fix.

The carry-forward audit (forced per M08 mission-debrief's recommendation) closed 2 stale items, routed 5 to this maintenance pass, and routed 8 to M09 as architectural-cluster candidates. The Architect overrode one M08 over-claim: F5 L01.5 fixed test infrastructure (`tests/conftest.py` `setdefault` env + session-end aiosqlite close), but the production singleton's lack-of-pool / lack-of-eviction is unchanged — re-opening as M09 fuel.

Three accessibility items merit Action Required: form-field errors are not programmatically associated with their input (A.6 carry-forward, second pass running); listbox keyboard semantics are missing across 3 sites despite a correct pattern existing in `section-nav.js:71-91` to lift; light-theme `--fg-muted`/`--fg-faint` fail WCAG AA on `--shell-chrome-bg` (F3.5 carry-forward).

The two operator-flagged M09 priorities (stop/cancel button + agent-loop reliability KI #6/#7; five module-skipped browser tests + paired `.new-entity-btn` DOM-visibility defect KI #3) are explicitly OUT of this maintenance scope. Per Architect: "These are reliability features [or product defects], not codebase health. M09 priority #1 and #2 are correct."
