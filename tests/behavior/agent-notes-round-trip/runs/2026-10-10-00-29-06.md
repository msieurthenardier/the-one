## Orchestrator Notes

- **Mode:** live (`SendMessage`). **Cache mode:** cold.
- **Preconditions** were established by the Flight Director as Orchestrator
  (operator away):
  - the scratch instance, with `DEV_MODE` and the stub flag;
  - an `ollama-local` provider and the `notes-probe` agent (all built-in tools
    on);
  - the `fetch_url` and `http_request` tool configs with
    `extra_allowed_hosts: ["127.0.0.1"]`;
  - the planted page served on `127.0.0.1:8793`;
  - the stub connector, with `peer-1` paired through the real code exchange.
- **Step 8 action:** step 7 had already written the pirate note, so it was
  kept and only the rule was added (spec branch).
- **Evidence-handling slip:** the Executor's step 7 capture overwrote
  `step-6-tab-list.png` and `step-6-a11y.txt` (renamed to `step-7-*`). Step
  6 had already been judged from the originals. Step 6's text evidence is
  intact.
- **Finding for the operator (outside this spec, recorded for the HAT):**
  - **What happened:** in step 10, with notes off, the prompt "List your saved
    notes." led the model to use the **built-in filesystem tools** (`glob`,
    `read_file`). It read three unrelated files in the repository's `.memory/`
    directory on the host and presented them as "the notes that have been
    saved". The file contents are deliberately not reproduced here.
  - **Why it is not a notes defect:** no notes tool ran and no notes rows
    changed.
  - **Why it matters:**
    - the agent's default filesystem reach includes the server's working
      directory;
    - with notes off, a model may still invent "notes" from files.
  - **Possible mitigations:** a sentence in the prompt saying notes are off,
    or reviewing the default filesystem scope.
- **Teardown:** the dev instance was stopped with `make down`, and the page
  server by its PID. The Executor stopped its Chromium by PID.
