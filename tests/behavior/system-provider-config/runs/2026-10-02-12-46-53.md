## Orchestrator Notes

- **Mode.** Live: SendMessage continuation. Cache mode was cold: a fresh Chromium profile and
  a fresh handoff, plus ignoreCache reloads.
- **Apparatus.** A CDP-driven headless Chromium on CDP port 9346 (Playwright
  `connect_over_cdp`, a persistent raw-CDP browser context, real input). This is the spec's
  named alternative to chrome-devtools; goldfinch's input is still broken.
- **Apparatus deviation, D10.** The first attempt fired the delete correctly, but the
  capture script then died on a JS SyntaxError that the Executor's own script edit had
  introduced. The late read-only capture showed the deleted state but could not evidence
  the focus clause. For the rerun D10r the Executor:
  1. re-created the provider through the API, under the same name the UI flow had produced;
  2. cold-loaded `#settings/providers` and opened the provider from its name link;
  3. armed and fired in one script, polling every ~200ms.

  The Validator judged that this does not weaken the checkpoint, because the UI create,
  edit and arm path had just been verified at D5–D9.
- **Focus after Save and Test.** Focus falls to BODY after Save, because the button
  disables, and after Test, because the button disables while the test runs and then
  re-enables. The spec asserts no focus there, so verdicts are unaffected. It is recorded
  for the Flight 3 debrief as an a11y item, alongside the same pattern in the agent editor.
- **Cross-client freshness.** In this run's tab, the concurrent run's provider showed
  "0 agents" at D5 and D6, while the other browser had an agent on it. The tab's agents
  list was fetched before that agent existed, and nothing in this tab invalidated it. A
  cold load (`shell-navigation-smoke` step 8) shows the correct "1 agent". This is
  expected per-client store behaviour, noted for the debrief.
